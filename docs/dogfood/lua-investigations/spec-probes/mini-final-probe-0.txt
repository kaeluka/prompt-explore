The API supports multi-stage composition investigations with a workflow Lua program. You can run two prompt stages in one investigation by supplying a workflow with lua_source and params, calling ctx.run_agent twice with different prompts.

Here is the exact POST /api/investigations JSON body for the two-stage candidate against scenario "scn-example" with the read_file tool, using model "open_router::openai/gpt-4.1-nano":

```json
{
  "scenario_id": "scn-example",
  "investigation": {
    "budget": {
      "max_steps_per_trace": 12,
      "max_tokens": 10000
    }
  },
  "workflow": {
    "lua_source": "return function(p,ctx) local file=ctx.call_tool('read_file',{path='config.json'}); if file.error then return {error=file.error} end; for attempt=1,3 do local a=ctx.run_agent{name='review-'..attempt,prompt=p.prompt,model=p.model,input=file.content}; if a.output~=nil then return a.output end end; return {delivered=false} end",
    "params": {
      "model": "open_router::openai/gpt-4.1-nano",
      "prompt": "Review this configuration."
    }
  }
}
```

Explanation:
- The scenario_id is "scn-example".
- The investigation budget allows up to 12 steps and 10,000 tokens.
- The workflow Lua source:
  - Calls the scenario tool "read_file" with argument {path: "config.json"}.
  - If the file call returns an error, returns that error immediately.
  - Otherwise, runs the agent up to 3 times with the prompt from params.prompt, the model from params.model, and the file content as input.
  - Returns the first successful output or {delivered=false} if none.
- The params supply the model and the review prompt.

---

How to read the output and handoff evidence:

1. After POSTing, you get an investigation id.
2. Poll GET /api/investigations/{id}/evidence to get the full conversation evidence.
3. In the evidence JSON:
   - The `workflow.invocations` array contains each ctx.run_agent call's details:
     - Each invocation has `name` (e.g. "review-1"), `prompt`, `model`, `input` (the file content), `output` (agent output), `failure` if any, and usage stats.
   - The `workflow.tool_calls` array contains direct calls to scenario tools:
     - You will see the read_file call with its arguments and the response (file content or error).
4. The `turns` array contains the PUT model turns, but for multi-stage workflows, the main evidence is in `workflow.invocations` and `workflow.tool_calls`.
5. Use the invocation's `turn_start` and `turn_end` to index into `turns` if you want to see the exact model completions.
6. The `execution.stop_reason` tells how the run ended (e.g. final_completion, step_budget).
7. The `resolved_inputs` shows the concrete inputs used for the scenario placeholders.

---

If you want a single prompt baseline for comparison, you would submit a separate investigation with the `put` shorthand instead of `workflow`.

This multi-stage orchestration is supported by the API as described in the OpenAPI spec under POST /api/investigations with the `workflow` field.
